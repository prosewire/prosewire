## Required services and origin

```dotenv
DATABASE_URL=postgres://…
BETTER_AUTH_SECRET=replace-with-at-least-32-random-characters
PROSEWIRE_PUBLIC_URL=https://publish.example.com
NEXT_PUBLIC_PROSEWIRE_PUBLIC_URL=https://publish.example.com
```

The public URL must be the external HTTPS origin seen by browsers. The web and worker must use the same Postgres database.

`PROSEWIRE_ANALYTICS_RETENTION_DAYS` controls raw page-view retention and defaults to 365. The worker deletes older events daily.

## Account bootstrap and email

```dotenv
PROSEWIRE_ALLOW_SIGN_UP=true
SMTP_URL=smtps://user:password@smtp.example.com:465
EMAIL_FROM=Prosewire <no-reply@example.com>
```

Production sign-up is disabled unless `PROSEWIRE_ALLOW_SIGN_UP=true`. Enable it to create the first owner, complete onboarding, then disable it unless open registration is intended. A valid, unexpired invitation link still allows the invited email address to create an account. SMTP is required in production for team invitations.

## Rolling and multi-instance deployments

```dotenv
NEXT_SERVER_ACTIONS_ENCRYPTION_KEY=<base64-encoded-32-byte-key>
NEXT_DEPLOYMENT_ID=release-2026-08-20
```

Use one stable server-action encryption key across every web replica and release. Give each release a deployment ID at container runtime so clients do not mix incompatible assets while a rollout is in progress. Every replica serving the same release must use the same ID.

## Local-only seed

`ADMIN_EMAIL`, `ADMIN_PASSWORD`, and `PROSEWIRE_DEFAULT_BLOG` are read only by the development seed. Production web startup never migrates or seeds the database.

## Security notes

- Never commit production environment files
- Keep Postgres on a private network
- Store API tokens as hashes and use the narrowest read/write scope
- Rotate a compromised API key by creating a replacement, changing the consumer, then revoking the old key
- Back up Postgres and test a restore before launch
